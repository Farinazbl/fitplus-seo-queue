# سامانه یکپارچه ایجنت‌های هوشمند — هسته + ایجنت‌های بله و سئو

این مخزن هسته سامانه است: ارکستریتور، صف کار، زمانبند، تشخیص تکرار، قوانین انتشار، صف تأیید انسانی، ثبت سوابق، API و داشبورد فارسی راست‌به‌چپ. ایجنت‌های واقعی (بله، سئو، اینستاگرام، یوتیوب، کمپین) در فاز ۲ و ۳ روی همین هسته اضافه می‌شوند.

## وضعیت فعلی نسبت به RFP

| بخش RFP | وضعیت |
| --- | --- |
| هسته: ارکستریتور، صف، Retry و صف خطا، هشدار، زمانبند، داشبورد RTL، نقش‌ها، تاریخچه، بکاپ، ردگیری هر محتوا | کامل و تست‌شده |
| سئو: دو مقاله در هفته، گزارش هفتگی، دریافت آمار GSC/Analytics از طریق `POST /api/metrics` | کامل؛ **خواندن مستقیم از GSC/Analytics نیاز به OAuth گوگل دارد و ساخته نشده** |
| بله مؤدیان و آموزش حسابداری: بازنویسی، قوانین بند ۳، تکرار متنی و معنایی ۱۵ روزه، فیلتر موضوعی، محافظ عدد/تاریخ، امضا، تأیید، انتشار با API بله | کامل؛ **تصویر متناسب هر پست ساخته نمی‌شود** (نیازمند سرویس تولید تصویر) |
| دکتر رژیم و فیت‌پلاس: بدون دخالت در روش فعلی، ثبت رویدادها (`POST /api/external/events`) و نمایش در داشبورد | کامل؛ لازم است سامانه فعلی آن‌ها رویدادها را بفرستد |
| کمپین منیجر: مخاطب، رضایت، لغو، سناریوهای بند ۴، توقف با خرید/تمدید، ساعات مجاز، سقف، کمپین دستی، حذف داده | کامل؛ **اتصال به پنل پیامک واقعی باید با مستندات پنل کارفرما نهایی شود** |
| شهر مجازی: عضویت داوطلبانه + تأیید مدیریتی، سقف ۴۰۰ هزار، جمعیت تأییدشده جدا از فالوور خام، انتخاب هفتگی ۱۰ نفر شفاف، رضایت نمایش، حذف داده، تولید متن ریلز/استوری | کامل؛ **دریافت خودکار کامنت/فالو از اینستاگرام و انتشار ریلز ساخته نشده** |
| اینستاگرام تغذیه | **فقط متن ساخته شد:** اسکریپت ریلز، متن اسلایدها و کپشن با محور هفتگی چرخشی (۴ محور) و صف تأیید علمی اجباری؛ **تولید ویدئو/تصویر و انتشار خودکار اینستاگرام ساخته نشده** |
| سه کانال یوتیوب (سناریو، ویدئو ۸ تا ۲۵ دقیقه، کاور، آپلود، آمار) | **ساخته نشده** — نیازمند تولید ویدئو، OAuth و ممیزی گوگل |
| پایگاه داده | SQLite؛ مهاجرت به PostgreSQL در پایدارسازی (فقط `app/db.py`) |

اتصال‌دهنده‌های اینستاگرام و یوتیوب هنوز نیستند؛ تا آن زمان خروجی هر ایجنت به وضعیت «آماده انتشار دستی» می‌رود.

## اجرا

نیازمندی‌ها: Python 3.11 یا بالاتر، و بسته‌های `starlette` و `uvicorn`.

```bash
pip install -r requirements.txt
export APP_TOKENS='sara=<توکن-حداقل-۱۶-نویسه>:admin,reza=<توکن-دیگر>:editor'
uvicorn app.main:app --host 0.0.0.0 --port 8000     # API + داشبورد
python -m app.worker                                 # زمانبند و اجراکننده وظایف
```

سپس `http://localhost:8000` را باز کنید و توکن را وارد کنید. با Docker: `docker compose up -d` (ابتدا `.env` را از `.env.example` بسازید).

## تنظیمات (متغیرهای محیطی)

| متغیر | پیش‌فرض | توضیح |
| --- | --- | --- |
| `APP_TOKENS` | الزامی | `نام=توکن:نقش` جدا‌شده با کاما؛ توکن حداقل ۱۶ نویسه |
| `APP_DB` | `agents.db` | مسیر پایگاه داده |
| `APP_TZ` | `Asia/Tehran` | منطقه زمانی زمانبندی |
| `APP_DEDUP_DAYS` | `15` | پنجره تشخیص تکرار |
| `APP_DEDUP_THRESHOLD` | `0.6` | آستانه شباهت |

توکن‌ها و کلیدهای سرویس‌ها فقط در محیط سرور نگهداری می‌شوند و به مرورگر نمی‌رسند.

## مسیر یک محتوا

`زمانبند ← وظیفه run_agent ← ایجنت پیش‌نویس می‌سازد ← قوانین ← تکراری؟ ← امضا ← تأیید انسانی (در صورت نیاز) ← وظیفه publish ← اتصال‌دهنده ← ثبت نتیجه`

تولید و انتشار دو وظیفه جدا هستند؛ پس خطای موقت مقصد فقط انتشار را دوباره تلاش می‌کند و محتوا دوباره ساخته (و تکراری) نمی‌شود. هر محتوا شناسه یکتا دارد و در داشبورد (بخش «محتوا ← ردگیری») یا `GET /api/content/{uid}` قابل پیگیری است.

## افزودن یک ایجنت جدید

1. در `app/agents/` کلاسی از `Agent` بسازید و متد `generate` را بنویسید که فهرستی از `Draft` برگرداند، سپس با `@register("نام")` ثبتش کنید.
2. در `app/seed.py` یا از داشبورد، `agent_type` ایجنت را روی همان نام بگذارید.
3. اگر مقصد جدید دارد، یک `Connector` در `app/connectors/` بنویسید و با `register(kind, connector)` ثبتش کنید.

قوانین انتشار، تشخیص تکرار، تأیید، retry و ثبت سوابق را ارکستریتور برای همه ایجنت‌ها یکسان انجام می‌دهد.

## پشتیبان‌گیری

`python scripts/backup.py` (نمونه برای cron روزانه). پایگاه داده را در مسیر `backups/` با مهر زمانی کپی می‌کند و ۳۰ نسخه آخر را نگه می‌دارد. پس از مهاجرت به PostgreSQL از `pg_dump` استفاده می‌شود.

## محدودیت‌های شناخته‌شده (صادقانه)

- اینستاگرام: API رسمی فهرست فالوورها را نمی‌دهد؛ ایجنت «شهر مجازی» بر پایه ثبت‌نام داوطلبانه و تأیید مدیریتی ساخته می‌شود.
- یوتیوب: آپلود خودکار عمومی پس از ممیزی پروژه توسط گوگل ممکن است؛ تا آن زمان ویدئوها خصوصی آپلود می‌شوند.
- بازنویسی محتوای کانال‌های دیگر مسئولیت حقوقی دارد؛ سامانه فقط قوانین و کنترل تکرار را اعمال می‌کند.
- ارقام KPI (۵۰ بازدید روزانه، ۲۰۰۰ مشترک) هدف‌اند، نه تضمین.

## ایجنت‌های فعال‌شدنی (فاز ۲، بخش اول)

| ایجنت | کار | اتصال |
| --- | --- | --- |
| `bale_tax`, `bale_accounting` | خواندن منبع، بازنویسی با مدل زبانی، اعمال قوانین، تأیید، انتشار | Bale Bot API |
| `seo` | دو مقاله در هفته از فهرست عبارت‌های کلیدی، با عنوان و توضیح متا | وردپرس (پیش‌فرض: پیش‌نویس) |

**راه‌اندازی هر ایجنت (از داشبورد یا API):**
1. متغیرهای محیطی سرور: `ANTHROPIC_API_KEY` یا `OPENAI_API_KEY` (اختیاری: `APP_LLM_PROVIDER`، `APP_LLM_MODEL`، `OPENAI_BASE_URL`) و توکن بات بله در `BALE_TOKEN` (برای همه کانال‌ها مشترک؛ اگر کانالی توکن جدا دارد در config آن `token_env` بدهید)، برای وردپرس `WP_APP_PASSWORD` (Application Password).
2. کانال را با `PUT /api/channels/{id}` تنظیم کنید: بله `{"config": {"chat_id": "@کانال", "token_env": "BALE_TOKEN_TAX"}}`، وردپرس `{"config": {"site": "https://...", "user": "bot", "password_env": "WP_APP_PASSWORD", "post_status": "draft"}}`. خود توکن را هرگز در config نگذارید (سامانه رد می‌کند). ربات باید ادمین کانال بله باشد.
3. منابع: برای وب‌سایت‌ها `rss:https://.../feed`؛ برای کانال‌هایی که ربات نمی‌تواند بخواند، متن خبر را با `POST /api/inbox` بفرستید و در منابع `inbox` بگذارید. برای سئو، هر خط یک عبارت کلیدی.
4. امضا و پرامپت کانال را بنویسید، ایجنت را فعال کنید و در حالت «تأیید دستی» چند روز بررسی کنید؛ بعد در صورت رضایت `auto` کنید.

**نکته حقوقی:** منبع‌ها باید مواردی باشند که کارفرما حق استفاده از آن‌ها را دارد. سامانه نام منبع و لینک را در خروجی رد می‌کند، اما بازنویسی اصیل و مسئولیت استفاده با کارفرماست.

اگر از قبل پایگاه داده ساخته بودید، با اجرای دوباره برنامه نوع ایجنت‌های `seo` و دو کانال بله به‌طور خودکار ارتقا می‌یابد.

## کمپین منیجر و شهر مجازی (راه‌اندازی)

- پیامک: `SMS_URL` و `SMS_TOKEN` را روی سرور بگذارید (درخواست JSON با `to`, `text`, `ref`؛ در صورت تفاوت پنل، فقط `app/connectors/sms.py` تغییر می‌کند). بدون این‌ها ارسال **با خطای روشن شکست می‌خورد** و وانمود به ارسال نمی‌شود. `APP_SMS_DRY_RUN=1` فقط برای آزمایش است.
- رویدادها را سامانه اپلیکیشن شما می‌فرستد: `POST /api/campaign/contacts` (با `consent`)، `POST /api/campaign/events` با `kind` یکی از `signup | purchase | subscription_start | renewal` (برای دو مورد آخر `end_at` الزامی است).
- متن پیامک‌ها و ساعات مجاز (پیش‌فرض ۹ تا ۲۱) از قوانین ایجنت `campaign_manager` ویرایش می‌شود: `{"templates": {"signup_1": "..."}, "quiet_hours": [9, 21], "daily_cap": 5000}`.
- شهر مجازی: ثبت‌نام با `POST /api/city/register`، کامنت‌ها با `POST /api/city/comments`، فالو با `POST /api/city/follow`، تأیید مدیریتی با `POST /api/city/verify` یا دکمه داشبورد. فقط «جمعیت اعلامی» را منتشر کنید.
- حذف داده: `DELETE /api/campaign/contacts/{id}` و `DELETE /api/city/citizens/{ig_id}` (ادمین).

اگر پایگاه داده از نسخه قبل دارید: زمان‌بندی‌های تازه (مثل گزارش هفتگی سئو) و نوع ایجنت‌ها فقط برای ایجنت‌های جدید یا «pending» خودکار اعمال می‌شود؛ بقیه را از داشبورد ویرایش کنید.
